# Confidence-probe reactivity study

PsychoPy implementation of the plan in `../Build-It-Yourself PsychoPy Study  Confidence-Probe Reactivity.md`, in two forms:
a Builder experiment (`confidence_probe.psyexp`, generated by `build_psyexp.py`) and a standalone Coder script
(`confidence_probe.py`). Builder was developed with PsychoPy 2026.2.4 (the manual in the parent folder is 2026.1.3);
pin and report the version you actually use.

## Files
| File | Purpose |
|---|---|
| `confidence_probe.psyexp` | Builder experiment (Python + JavaScript Code components, type *Both*) |
| `build_psyexp.py` | Regenerates the `.psyexp`: `"C:/Program Files/PsychoPy/python.exe" build_psyexp.py` |
| `confidence_probe.py`, `helpers.py` | Standalone Coder version and its pure-Python helpers (`python helpers.py` = self-test) |
| `conditions/` | `two_orientations.csv`, `quest_conditions.csv` |
| `simulate_session.py` | Runs the `.psyexp` with fake keypresses/clicks: `... simulate_session.py no_probe\|sparse_probe\|full_probe` |
| `verify_output.py` | Checks a data CSV against the plan's test matrix: `... verify_output.py data/<file>.csv` |
| `docs/data_dictionary.md` | Output columns |

Enter `participant` in the start dialog and leave `condition` as `auto` (counterbalanced). For testing you can type
`no_probe`, `sparse_probe` or `full_probe` to force a condition. Data go to `data/`.
Coder version: `python confidence_probe.py` (add `--quick` for a short windowed technical run).
Once the `.psyexp` is opened in Builder, Builder is the source of truth; re-running `build_psyexp.py` overwrites it.

## Session
consent -> condition allocation -> instructions (neutral screen for `no_probe`) -> 12 practice (with feedback) -> 40 QUEST calibration
-> 40 baseline (no confidence, fixed 1.5 s post period) -> 4 x 40 main -> timed (3 s) "experiment finished" message,
which closes automatically. There are no post-task questions and no debrief.

- Choice: F = left tilt (`tiltSign` -1), J = right tilt (+1). Grating shown for 150 ms from onset; response window
  1.5 s from onset; the trial ends at the first response made after 150 ms, or at 1.5 s.
- The fixation cross is not shown while the grating is on screen. It appears on the frame the grating is removed
  (Builder: conditional start on the grating's status, so there is no gap or overlap) and stays until the decision ends.
- Post-decision period is always 1.5 s; confidence keys 1-6 never end it early. On probe trials the confidence prompt
  is centred with no fixation cross; non-probe trials show the cross for the same 1.5 s.
- Sparse schedule: exactly 10 probes in each block of 40. Missed choices get no probe
  (`probeOriginallyScheduled` keeps the randomised value).
- Practice feedback: "Correct" green, "Incorrect" red, "Too slow" (no response in the window) yellow.

## Differences from the plan, and why
- The condition variable in code is `probeCondition`, not `condition` (PsychoPy's staircase loop overwrites `condition`);
  the chosen condition is still saved as the `condition` column from the start dialog.
- Calibration uses `calibTiltSign`/`calibCorrAns` (assigning `tiltSign`/`corrAns` in code shadows the loop variables).
- `Save csv file` is off (the per-loop save crashed in PsychoPy 2026.2.4); the wide CSV is saved.
- The QUEST loop carries an extra `conditionsFile` entry so this PsychoPy build can compile it; Builder may warn about it.
- Post-task questions (global performance/confidence, strategy, suspicion) and the debrief were dropped by request.
  The plan's hypothesis-awareness sensitivity analysis is therefore not possible with this version.
- Calibration omissions feed QUEST as incorrect; threshold = median of the last 10 levels (clamped 1-15 deg),
  with `calibrationAtBoundary` flagging clamped values.

## Counterbalancing
A Counterbalance Routine (`conditionAllocation`, after consent) allocates one of 3 equally likely groups:
0 = `no_probe`, 1 = `sparse_probe`, 2 = `full_probe` (mapping in the `initialize` routine's Begin Routine code).
Both Python and JavaScript are written. `condition = auto` uses the allocated group; any explicit condition overrides it.
The resolved condition is saved in `assignedCondition` (and `conditionSource` = `counterbalance` or `manual`), overwrites the
`condition` column, and the routine saves `conditionAllocation.group` / `.remaining`. `verify_output.py` reads `assignedCondition`.
- Local runs use a shelf file next to the experiment: 2 slots per group x 15 repeats = 30 per group (change in Builder); once all 90 slots are used, further sessions end immediately (handled in `initialize`; PsychoPy's built-in end-on-depletion is off because it also ends the 90th participant). Allocation is
  random with caps, so small samples can be unbalanced; use small slot batches and refill for tighter balance.
- Online: upload to Pavlovia, open **Dashboard -> Shelf**, create a record whose key is exactly `conditionAllocation`
  (scope: experiment, type: Counterbalance) with groups `0`, `1`, `2`, 2 slots each and 15 repetitions (matches the Builder defaults). Slots are reserved when a participant
  starts, so dropouts can leave groups uneven.
- `assignedCondition`/`conditionSource` are written once (on one row); the `condition` column holds `auto` on the rows before allocation and the
  real condition on every trial row after it. Analyse the trial rows (or forward-fill `assignedCondition`).
- `conditionAllocation.group` is saved as a string (`'0'`, `'1'`, `'2'`) locally; the code converts it with `int()`/`Number()`.

## Verification status
Verified (PsychoPy 2026.2.4, Builder version):
- The `.psyexp` compiles to Python and JavaScript; the Coder script and `helpers.py` compile, and the helpers self-test passes.
- Simulated full sessions of `no_probe`, `sparse_probe` and `full_probe` (fake keypresses) each passed all checks in
  `verify_output.py`: row counts, 4 blocks x 40, 20 per orientation per block, probe counts 0/40/160 with 10 per block,
  confidence empty on non-probe rows, no probe after a missed choice, scoring consistent.
- A per-frame capture of practice trials showed clean grating-to-cross handoffs (no overlap, no empty frames).
- Counterbalancing (`condition = auto`, local shelf): four simulated full sessions each passed `verify_output.py`, and the saved
  `assignedCondition` matched the allocated group and the probe counts (group 0 -> `no_probe`, 1 -> `sparse_probe`,
  2 -> `full_probe`; `conditionSource` = `counterbalance`). Three concurrent runs were allocated `full_probe`, `sparse_probe`,
  `full_probe` and the shelf counts matched (one slot used per allocation). Allocation is random with caps, so three runs
  need not cover all three groups. Concurrent launches must be staggered and use distinct participant IDs
  (`simulate_session.py` does this by process ID); a simultaneous start crashed one run when both created `data/`.

NOT verified:
- Real participant timing on your display (the 1.5 s post period, 150 ms exposure) and any photodiode/frame-drop check.
- Real clicking and calibration: the simulation's responses are fake (about 80% correct whatever the tilt), so its
  calibrated tilts (3.4 to 11.7 degrees) mean nothing; check `calibratedTiltDeg` and `calibrationAtBoundary` in pilot data.
- Online counterbalancing (Pavlovia Shelf setup), and a long-run check of group balance across many sessions.
- The tilt-sign check: confirm on your screen that -1 looks left-tilted (PsychoPy `ori` is positive-clockwise).
- The JavaScript/online version (no Node available to syntax-check; Pavlovia not tested).
- The Coder script on hardware, and the Coder version of the latest display changes. The Coder script has no counterbalancing
  (condition is chosen in its start dialog).
